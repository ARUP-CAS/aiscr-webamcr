# Usage: commit Fedory až po commitu DB (#4453, část A)

- **When:** 2026-11-12
- **Agent / runtime:** Claude Code (VS Code extension)
- **Model / backend:** `claude-sonnet-5-5`
- **What:** Podle části A issue #4453 se commit Fedora transakce už neprovádí synchronně uvnitř DB transakce, ale přes `transaction.on_commit(fedora_transaction.mark_transaction_as_closed)`. Zápisy metadat do Fedory zůstávají uvnitř DB transakce. `User.save_metadata(close_transaction=True)` teď odkládá commit stejně jako `ModelWithMetadata.save_metadata`. V `adb/views.py` (`smazat_vb`), `dj/views.py` (`smazat`) a `dokument/views.py` (`smazat`) se commit plánuje, když `delete()` smazal aspoň jeden řádek (původně se větvilo podle vždy pravdivé dvojice, takže větev s rollbackem byla nedosažitelná). Záměrně beze změny zůstaly `api/views.py` (3×), `fedora_management/views.py` a `pid/views.py`: zachycují selhání commitu Fedory a vracejí ho jako chybovou odpověď, což by po přesunu do `on_commit` nešlo. Část B issue a outbox (mimo rozsah issue) se neřešily. Založena lokální větev `bugfix/4453-fedora-commit-on-commit` z `test` bez upstreamu.
