# Usage: commit Fedory až po commitu DB (#4453, část A)

- **When:** 2026-11-12
- **Agent / runtime:** Claude Code (VS Code extension)
- **Model / backend:** `claude-sonnet-5-5`
- **What:** Podle části A issue #4453 se commit Fedora transakce už neprovádí synchronně uvnitř DB transakce, ale přes `transaction.on_commit(fedora_transaction.mark_transaction_as_closed)`. Zápisy metadat do Fedory zůstávají uvnitř DB transakce. `User.save_metadata(close_transaction=True)` teď odkládá commit stejně jako `ModelWithMetadata.save_metadata`. V `adb/views.py` (`smazat_vb`) se commit plánuje jen při úspěšném smazání, dříve se po `rollback_transaction()` volal i commit. Záměrně beze změny zůstaly `api/views.py` (3×), `fedora_management/views.py` a `pid/views.py`: zachycují selhání commitu Fedory a vracejí ho jako chybovou odpověď, což by po přesunu do `on_commit` nešlo. Část B issue a outbox (mimo rozsah issue) se neřešily. Založena lokální větev `bugfix/4453-fedora-commit-on-commit` z `test` bez upstreamu.
- **Impacted:** `webclient/adb/signals.py`, `adb/views.py`, `arch_z/signals.py`, `core/signals.py`, `core/views.py`, `dj/signals.py`, `dj/views.py`, `dokument/signals.py`, `dokument/views.py`, `heslar/signals.py`, `pas/signals.py` (jen komentář), `uzivatel/admin.py`, `uzivatel/models.py`, nový test `core/tests/test_fedora_commit_after_db_commit.py`, upravený docstring v `core/tests/test_delete_signals_fedora_before_commit.py` a tento záznam.
- **Verification:** `compileall` bez chyb, `black`, `isort` a `flake8` bez nálezů. `core.tests.test_fedora_commit_after_db_commit`, `core.tests.test_delete_signals_fedora_before_commit` a `core.tests.test_soubor_delete_concurrent` dohromady 37 testů OK. Nové testy po dočasném vrácení původního kódu selhaly (6 selhání). Views `adb`, `dj`, `dokument`, `uzivatel/admin.py` nemají test a integrační test proti skutečné DB a Fedoře neproběhl.
- **Close-out:** Změny zůstávají necommitnuté na lokální větvi; neproběhlo staging, commit, push ani založení PR. Chyba commitu Fedory po DB commitu se ve views s `@handle_fedora_error` a v `except FedoraError` kolem uzavření (`core`, `dokument`) už nezachytí a skončí jako HTTP 500.
